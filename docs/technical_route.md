# Phase 2 技术路线

## 路线选择

本项目采用路线 A：**CSV 主流程 → Streamlit → 可选 IFC**。在 Phase 2 只建立可复现的配置、schema 和样例 CSV 基础，不提前实现后续读取器、清洗器、流水线编排或界面。路线 A 先固定数据契约，再由后续阶段在同一契约上接入业务模块；IFC 适配器属于后续阶段，不改变本阶段的样例验收边界。

样例文件代表“程序演示数据”，不是一个真实项目。任何单价说明都必须使用以下原文：**本项目单价为教学示例数据，不用于正式工程造价。**

## 本阶段唯一数据流

```text
带版本号的配置
        ↓
load_project_config / schema 契约校验
        ↓
固定种子 deterministic sample generator
        ↓
sample CSV
        ↓
pytest 样例与配置校验
```

### 1. 版本化配置

`configs/` 下的字段映射、类别、楼层、材料、命名、质量规则和教学单价文件共同构成 Phase 2 输入。每个 JSON 配置带 `config_version`，schema 契约带可核对的版本信息；未知键、重复映射和非法枚举应在配置校验阶段被发现。相对仓库路径是配置追踪的唯一文档表达，例如 `configs/field_mapping.json` 和 `configs/sample_unit_prices.csv`。

### 2. `load_project_config` 与 schema

`load_project_config` 负责读取并检查上述配置，schema 负责定义 18 个标准字段、类型、可空性和枚举。两者是本阶段的边界：它们只确认配置与字段契约可被后续模块使用，不执行工程量、造价或质量计算。字段的原始值、来源文件和原始行号规则见 `docs/data_dictionary.md`。

### 3. 确定性样例生成器

样例生成器使用配置中的固定种子 `20260804`、记录数和字段顺序，产出不少于 200 行的固定 CSV；项目设计规格要求首批样例为 240 行，并覆盖标准化楼层 `一层`、`二层`、`三层` 及 `IfcBeam`、`IfcColumn`、`IfcSlab`、`IfcWall`、`IfcDoor`、`IfcWindow`。生成器必须稳定呈现规格约定的缺失、重复、零值、命名、单位和缺价样例，以便测试直接读取文件核对，而不是依据日志猜测。

生成结果写入相对路径 `data/sample/sample_elements.csv`；该文件和 `data/sample/sample_manual_validation.csv` 仅供教学演示与测试，不代表真实工程数据。

### 4. 样例 CSV 与测试

测试读取生成文件，核对记录数、字段顺序、楼层/类别覆盖、固定种子下的重复生成一致性及预置异常数量。配置测试确认版本、映射和标准字段契约可加载。Phase 2 的验收只记录实际测试结果；不在路线文档中预先宣称通过率、耗时、精度或规模指标。

## 明确的后续阶段（本阶段不实现）

以下组件不属于 Phase 2 数据流，当前文档只列出边界和后续顺序，不提供实现：

1. **CSV reader**：后续负责 UTF-8-SIG、UTF-8、GBK 尝试、原始行号保留和字段别名初步映射；当前不实现读取逻辑。
2. **Cleaner**：后续负责空值、数值、单位、类别、楼层、材料和 GUID 的标准化，并保留清洗事件；当前不实现清洗逻辑。
3. **Pipeline**：后续按 reader → cleaner → quantity → cost → quality → report 编排端到端处理；当前不实现编排或业务计算。
4. **Streamlit**：后续提供项目概览、工程量分析、构件查询、数据质量检查、误差分析和报表导出页面；当前不实现上传、筛选或展示。
5. **IFC reader**：后续以可选 IfcOpenShell 薄适配器接入六类 IFC 构件；当前不导入 IFC，也不让可选依赖进入样例流程。

这些组件都必须复用本阶段稳定的 schema 与配置边界，不能在页面或脚本中复制字段映射和计算规则。

## 本阶段不扩展的内容

本阶段不新增依赖、不建立通用抽象、不添加性能或指标承诺，也不把后续业务实现写入配置文档。任何实现代码应在后续任务的 `src/`、`scripts/` 或 `tests/` 边界内完成；本路线只描述顺序、输入、输出和验收证据。
